    2. Implement registerSecret(secret: string | undefined): void that adds strings with length greater than 2 to the registry.
    3. Implement redactString(text: string): string that:
       - Replaces all registered secret strings with `[REDACTED]`.
       - Replaces embedded userinfo in HTTP/HTTPS URLs using regex `([a-zA-Z][a-zA-Z0-9+.-]*:\/\/)[^/]+@` replaced by `$1[REDACTED]@`.
       - Replaces HTTP Basic and Bearer Authorization headers using regex `Bearer\s+[A-Za-z0-9-_.]+` and `Basic\s+[A-Za-z0-9+/=]+` with `Bearer [REDACTED]` and `Basic [REDACTED]`.
       - Replaces LiveSync setup URIs using regex `obsidian:\/\/livesync\?[^\s"']+` with `obsidian://livesync?[REDACTED]`.
    4. Implement redactError(err: unknown): Error that creates a clean Error instance whose message and stack trace have been scrubbed via redactString.
    5. Implement redactObject(obj: unknown): unknown that recursively clones objects and arrays, scrubbing string values via redactString and masking sensitive keys (matching password, passphrase, secret, auth, token, credential).
    6. Wire SecretRedactor into src/diagnostics/logger.ts so that all logger output passes string messages and metadata payloads through redactString and redactObject before JSON serialization.
    7. Create tests/unit/redaction.test.ts with unit test cases testing URL userinfo redaction, Authorization header redaction, setup URI redaction, stack trace scrubbing, and recursive object redaction.

       - VaultConfigSchema: z.object({ path: z.string().min(1) }).strict().
       - StateConfigSchema: z.object({ path: z.string().min(1).optional() }).strict().
       - EncryptionConfigSchema: z.object({ enabled: z.boolean().default(false), passphrase: SecretRefSchema.optional() }).strict().
       - LiveSyncConfigSchema: z.object({ remote: CouchDbConfigSchema, vault: VaultConfigSchema, state: StateConfigSchema.default({}), encryption: EncryptionConfigSchema.optional() }).strict().

    2. In src/config/secrets.ts, implement resolveSecret(ref: SecretRef | undefined, env: NodeJS.ProcessEnv): Promise<string | undefined>.
       - If ref is string, return it.
       - If ref has fromEnv, read env[ref.fromEnv]. If missing, throw an Error naming the missing environment variable.
       - If ref has fromFile, resolve the path and read the file content using node:fs/promises.readFile, trimming trailing whitespace. If file is missing or unreadable, throw an Error naming the unreadable secret file.

<threat_model>
### STRIDE Register

| Threat ID | Category | Threat Description | Disposition | Mitigation Strategy |
|---|---|---|---|---|
| T-01-01 | Information Disclosure | Plaintext database passwords or encryption passphrases stored in tracked YAML configuration or committed to version control. | Mitigated | SecretRef schema supports `{ fromEnv: "VAR_NAME" }` and `{ fromFile: "/path" }` plus default environment variable fallbacks so configuration files contain no secrets (CONF-02). |
| T-01-02 | Elevation of Privilege / Tampering | Malicious or misconfigured vault destination path (`/`, `/etc`, `~`, `../../`) causes future synchronization to overwrite sensitive system or user files. | Mitigated | `loadConfig` canonicalizes vault paths with `path.resolve`, strictly forbids root `/`, home `~`, parent escapes, and overlapping state directories before any side effect (CONF-03). |
| T-01-03 | Information Disclosure | Passwords, passphrases, Bearer tokens, or setup URIs leak in stderr logs, console output, or unhandled exception stack traces. | Mitigated | `SecretRedactor` scrubs all registered secrets, embedded Basic auth in URLs, Authorization headers, LiveSync setup URIs, and deep-scrubs `Error` stack traces across all logging channels (SAFE-04). |
| T-01-04 | Tampering | Unrecognized configuration parameters silently accepted, leading to unexpected operational modes or bypass of safety checks. | Mitigated | All Zod schemas enforce `.strict()`, rejecting any unknown YAML keys at parse time before processing. |
| T-01-SC | Supply Chain | Compromised third-party packages or malicious version drift in dependencies. | Mitigated | Exact dependency pinning: `@vrtmrz/livesync-commonlib@0.1.21` (integrity sha512-AGuZ3eqBP37HJXEkTSpJ5M5bvTx2lYNq+6Q5NuCPZeGdbv7g6cujGvccVR5ozGfKdHGSyFZND5x1oFS9crRhUg==), `yaml@2.9.0`, `zod@4.5.4`, `typescript@5.9.3`, `vitest@4.1.11`. |

### Trust Boundaries

1. **Operator / CLI Input Boundary:** CLI arguments (`--config`, `--json`) and YAML file contents are untrusted. They are strictly validated by Zod and path normalizers before use.
2. **Environment & Filesystem Secrets Boundary:** Environment variables and external secret files are read just-in-time and immediately registered in `SecretRedactor` memory; they are never written to disk or logs.
3. **Internal Diagnostic Output Boundary:** All data flowing to stdout or stderr passes through `SecretRedactor` filtering.
</threat_model>
