<context>
This is Plan 3 of Phase 1. It completes the Guarded Read-Only Admission walking skeleton by connecting the read-only CouchDB probe from Plan 01-02 to compatibility negotiation, cryptographic passphrase authentication, durable SQLite persistence, and structured diagnostics.

Per requirement CONF-05, the client must pull and adopt compatible remote tweaks (hashAlg, customChunkSize, chunkSplitterVersion) while blocking on incompatible differences (encrypt, usePathObfuscation, etc.), locked databases, or future protocol versions (>12).

Per requirements CONF-06 and SAFE-06, the user receives a stable compatibility report with the remote fingerprint, SHA-256 negotiated-settings hash, capabilities, and blockers in human-readable or JSON Lines format, with stable numeric exit codes for each failure category.
</context>

<threat_model>
### STRIDE Register

| Threat ID | Category | Threat Description | Disposition | Mitigation Strategy |
|---|---|---|---|---|
| T-03-01 | Elevation of Privilege / Tampering | Incompatible, unknown, or future LiveSync version records admitted, causing silent corruption or format divergence in subsequent phases. | Mitigated | `negotiateCompatibility` fails closed on `version > 12`, missing milestone, locked database, or unrecognized remote preferred settings (`UNKNOWN_REMOTE_SETTING`) with structured blockers and exit code 3 (CONF-05). |
| T-03-02 | Information Disclosure | Decryption passphrase or decrypted syncinfo plaintext written to SQLite state store or printed in stdout reports. | Mitigated | `AdmissionRepository` schema stores only public markers, hashes, and update_seq; passphrases and plaintext data are strictly excluded (CONF-06, SAFE-04). |
| T-03-03 | Spoofing / Authentication Bypass | Client admits an encrypted database without verifying that the supplied passphrase can decrypt remote data. | Mitigated | `verifySyncinfo` authenticates passphrase via Web Crypto HKDF/AES-GCM against remote PBKDF2 salt before admission is granted (CONF-05). |
| T-03-04 | Repudiation / Misconfiguration | Discrepancy between human-readable CLI report and machine-readable JSON Lines diagnostics leads to automation misinterpreting failures as success. | Mitigated | Both formatters share a single typed `CompatibilityReport` source of truth and map to the exact same numeric `EXIT_CODES` (SAFE-06). |
| T-03-05 | Tampering | Silent remote database mutation occurs during inspection unnoticed by the coordinator. | Mitigated | `runInspectCommand` captures pre/post snapshots via `ZeroMutationVerifier`, verifies `update_seq` and revision equality, and aborts with outcome `MUTATION_VIOLATION` (exit code 6) if mutation is detected (SAFE-02, CONF-04). |
| T-03-SC | Supply Chain | Unaudited crypto library used for Web Crypto / PBKDF2 / HKDF operations. | Mitigated | Zero external crypto dependencies; relies exclusively on standard Web Crypto API built into Node.js 24 (`globalThis.crypto.subtle`). |

### Trust Boundaries

1. **Remote CouchDB Document Boundary:** All remote metadata documents (versioning, milestone, sync parameters, syncinfo) are treated as untrusted until schema validation and version checks succeed.
2. **Cryptographic Key Boundary:** Encryption keys derived from passphrases remain ephemeral in memory and are discarded immediately after syncinfo verification.
3. **Local State Boundary:** The SQLite database is created in `config.state.path`, strictly outside the vault directory, ensuring synchronized files cannot corrupt or overwrite application state.
</threat_model>
