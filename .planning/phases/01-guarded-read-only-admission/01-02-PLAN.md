<objective>
Implement the guarded HTTP transport layer that mechanically blocks mutating methods and administrative endpoints, and build the read-only CouchDB protocol inspector with verified zero-mutation proof against real CouchDB 3.5.2.1.
</objective>

<execution_context>

</execution_context>

<context>
Per research in 01-RESEARCH.md, Commonlib's built-in negotiation methods (such as checkRemoteVersion, checkSyncInfo, and ensureRemoteIsCompatible) are not read-only: they issue HTTP PUT requests to create default documents or update milestone timestamps when records are missing or stale.

Per requirements SAFE-01 and SAFE-02, the application must never invoke administrative operations (purge, compact, security, replicator, design docs) and first-contact admission traffic must be restricted to an explicit read-only HTTP method and endpoint allowlist.

Per requirement CONF-04, the inspector must read database identity, LiveSync version markers, lock state, security parameters, preferred tweaks, and representative records without modifying remote state.
</context>

       - Method Check: strictly ALLOWED_METHODS = new Set(['GET', 'HEAD']). If method is PUT, POST, DELETE, PATCH, or any other method, immediately throw MutationAttemptBlockedError before network transmission.

Resolve the target URL and verify its origin matches allowedBaseUrl.origin. Reject cross-origin redirects with EndpointDisallowedError. Re-run through guardedFetch.
    3. In src/security/capabilities.ts, implement capability branding:

       - Define AdmissionCapability interface branded with a private symbol, requiring validated remote fingerprint and settings hash.

    4. Create tests/unit/transport-guard.test.ts verifying:

       - Administrative endpoints (_purge, _compact, _security, etc.) throw EndpointDisallowedError.
       - Requests to different origins or ports throw EndpointDisallowedError.

<threat_model>
### STRIDE Register

| Threat ID | Category | Threat Description | Disposition | Mitigation Strategy |
|---|---|---|---|---|
| T-02-01 | Tampering | Unintentional mutation of CouchDB during inspection due to upstream setup helper invocation or unexpected HTTP write methods. | Mitigated | Custom read-only inspector uses pure `GET`/`HEAD` queries; `createGuardedFetch` throws `MutationAttemptBlockedError` on any write method; pre/post `update_seq` verification guarantees zero change (SAFE-02, CONF-04). |
| T-02-02 | Tampering / Repudiation | Accidental invocation of CouchDB administrative or destructive APIs (`_purge`, `_compact`, `_security`, `_replicator`, `_design`) through the client. | Mitigated | `createGuardedFetch` enforces an audited path denylist blocking all administrative endpoints before network transmission (SAFE-01). |
| T-02-03 | Information Disclosure | HTTP 3xx redirect to a third-party server forwards Basic authentication credentials or exposes query parameters. | Mitigated | `createGuardedFetch` sets `{ redirect: 'manual' }`, verifies redirect Location has identical origin, and rejects cross-origin redirection. |
| T-02-04 | Spoofing | Client connects to a malicious server mimicking CouchDB on an unexpected origin or port. | Mitigated | Target URL origin is strictly checked against the pre-configured base URL origin on every single dispatch. |
| T-02-SC | Supply Chain | Testcontainers CouchDB or container image compromised or pulled from untrusted source. | Mitigated | Docker image is pinned to official `couchdb:3.5.2.1` image digest pre-cached on the local Docker host. |

### Trust Boundaries

1. **Application / Network Dispatch Boundary:** All HTTP requests pass through `createGuardedFetch`. Application logic has no access to raw `globalThis.fetch`.
2. **CouchDB HTTP Wire Boundary:** All communication with CouchDB is restricted to read-only queries against existing databases; database creation is never attempted.
</threat_model>
