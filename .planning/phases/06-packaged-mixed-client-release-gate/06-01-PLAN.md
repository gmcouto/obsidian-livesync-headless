<task type="auto" tdd="true">
  <name>Task 2: Implement local status command for offline vault health inspection</name>
  <files>src/cli/commands/status.ts, tests/unit/status-command.test.ts</files>
  <behavior>
    - `runStatusCommand(options: StatusCommandOptions): Promise<number>`:
      - Loads configuration from `options.configPath` to resolve `vaultRoot` and `stateDirectory`.
      - Checks if the SQLite database (`state.db`) exists. If missing, reports outcome `UNCONFIGURED` / `CLEAN` with 0 tracked files.
      - If database exists, initializes `SqliteClient` and queries:
        - `AdmissionRepository.getLatestAdmission()` -> admitted status, couchdbUrl (redacted), databaseName, settingsHash, admittedAt.
        - `WriteGrantRepo.getActiveGrant()` -> active grant status, grantId, bootstrapGeneration, issuedAt.
        - `CheckpointRepository.getLastCheckpoint()` -> hasCheckpoint, lastUpdateSeq, completedAt.
        - `file_provenance` table -> count of tracked files.
        - `quarantine_index` table -> count of quarantined files.
      - Returns `StatusReport` structured object with `type: 'status_report'`.
      - Emits human-readable status overview or JSON Lines output when `options.json` is true.
      - Returns exit code 0 on successful inspection.
  </behavior>

Implement `src/cli/commands/status.ts`. Write unit tests in `tests/unit/status-command.test.ts` testing clean state, admitted state with active grant, unadmitted state, and JSON/human formatting with mocked SQLite databases.
