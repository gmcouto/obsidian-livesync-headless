## Phase Goal

**As a** vault operator, **I want** pull planning to distinguish unchanged files (`noop`), deleted files (`quarantine-delete`), and new files (`create`), and I want leftover staging files to be automatically cleaned on startup, **so that** repeated pull runs are deterministic and interrupted operations can be seamlessly resumed.

<objective>
Implement provenance-aware recoverable pull planning and orphan staging file cleanup:
1. Extend `PullAction` to include `kind: 'noop'` and `kind: 'quarantine-delete'`.
2. Implement `buildRecoverablePullPlan` reconciling remote observations with local SQLite provenance and local file stats.
3. Implement `cleanupOrphanStagingFiles` in `src/filesystem/orphan-cleanup.ts`.
4. Update `preflightVault` to clean stale `.ols-tmp-*` files prior to file inventory checks.

Purpose: Guarantee idempotent zero-write pull plans and crash-safe resumption capability.
Output: Reconciled pull planning logic and orphan cleanup routines verified by unit tests.
</objective>

    - buildRecoverablePullPlan generates 'create' when remote doc is live and either revision or hash differs from local provenance or file is missing

       - Extend `PullAction` union with:
         - `{ kind: 'noop'; path: string; sourceRevision: string; contentSha256: string }`

       - Export interface `LocalFileInspection { readonly exists: boolean; readonly contentSha256?: string }`.
       - Implement and export `buildRecoverablePullPlan(observations, existingProvenance, localFiles)`:
         - Group decoded observations by vault path.
         - Filter out special / ignored observations (`skip-special`, `skip-ignored`).
         - Check for decode failure observations -> emit `block`.
         - For each grouped path:
           - Check for conflict leaves: if multiple non-deleted leaves exist -> emit `block` with code `CONFLICT_LEAVES`.
           - If all leaves are deleted:
             - Check if local file exists (from `localFiles.get(path)?.exists`).
             - If local file exists -> emit `kind: 'quarantine-delete'`.
             - If local file absent -> emit `kind: 'skip-logical-delete'`.
           - If single live leaf:
             - Compute leaf content SHA-256.
             - Check `existingProvenance.get(path)` and `localFiles.get(path)`.
             - If local file exists AND provenance exists AND `provenance.remoteRevision === leaf.sourceRevision` AND `provenance.contentSha256 === computedSha256` AND `localFile.contentSha256 === computedSha256`:
               -> emit `kind: 'noop'`.
             - Otherwise -> emit `kind: 'create'`.
       - Update `serializePullActions` to handle `noop` (including `contentSha256`) and `quarantine-delete`.
       - Ensure backward compatibility with existing `buildPullPlan` for callers passing only observations.
    2. Create `tests/unit/recoverable-pull-plan.test.ts`:
       - Test exact match yields `noop`.
       - Test content difference or rev difference yields `create`.
       - Test missing local file despite provenance record yields `create`.
       - Test deleted remote doc with local file yields `quarantine-delete`.
       - Test deleted remote doc without local file yields `skip-logical-delete`.
       - Test conflict leaves yield `block` with `CONFLICT_LEAVES`.
       - Test serialization strips bytes and includes `contentSha256` for `noop`.
    3. Update `tests/unit/pull-plan.test.ts` to verify existing tests continue to pass.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local filesystem files | User files in vault must never be deleted by orphan cleanup unless strictly matching `.ols-tmp-*` prefix |
| Remote document streams | Remote tombstones must not be interpreted as valid note bodies or overwrite local files |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-05 | Tampering / Data Loss | cleanupOrphanStagingFiles | high | mitigate | Strict prefix check (`entry.name.startsWith(OLS_TMP_PREFIX)`); never delete non-temporary files or standard dotfiles |
| T-03-06 | Denial of Service | preflightVault | medium | mitigate | Orphan cleanup prevents interrupted pull runs from causing permanent `UNPROVEN_LOCAL_FILE` locks on restart |
| T-03-07 | Spoofing | buildRecoverablePullPlan | medium | mitigate | Match both `remoteRevision` AND `contentSha256` from SQLite provenance against local file bytes before classifying as `noop` |
</threat_model>
