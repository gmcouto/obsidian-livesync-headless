<objective>
Implement the storage, arming, and security infrastructure required for authorized remote write access in Phase 4.

Purpose: Remote writes must never occur implicitly or unrestrictedly. This plan provides the durable 5-tuple write grant mechanism in SQLite (CONF-07, CONF-08) and the restricted write transport guard that enforces the minimum required CouchDB HTTP operations while blocking destructive and administrative endpoints (SAFE-03).
Output: Migration 005 in `sqlite.ts`, `WriteGrantRepo`, `createArmedGuardedFetch`, capability tokens, and comprehensive unit tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator -> CLI Command | Untrusted CLI flags and arguments requesting write arming |
| Headless Client -> CouchDB Transport | HTTP requests generated during synchronization; must not execute forbidden verbs |
| SQLite State -> Runtime Capability | Stored write grant tokens used to authorize mutating network actions |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Elevation of Privilege | `WriteGrantRepo` | critical | mitigate | Bind write grant to 5 explicit tuples (remote fingerprint, vault root, settings hash, commonlib version, bootstrap generation) and auto-revoke immediately on drift (CONF-07, CONF-08). |
| T-04-02 | Tampering | `createArmedGuardedFetch` | critical | mitigate | Deny HTTP DELETE and administrative endpoints (`/_purge`, `/_compact`, etc.) at the transport level regardless of caller intent (SAFE-03). |
| T-04-03 | Information Disclosure | `transport-guard.ts` | high | mitigate | Inspect redirect headers and deny cross-origin redirects; redact credentials in error messages. |
</threat_model>
