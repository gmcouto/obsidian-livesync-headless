  <name>Task 1: SyncCoordinator and CLI commands (arm and sync)</name>
  <files>src/domain/sync-coordinator.ts, src/cli/commands/arm.ts, src/cli/commands/sync.ts, src/cli/index.ts, tests/unit/sync-coordinator.test.ts, tests/unit/sync-command.test.ts</files>
  <behavior>
    - `SyncCoordinator` orchestrates the 6 stages:
      1. Preflight check: vault accessibility, quarantine directory safety, remove stale `.ols-tmp-*` staging orphans.
      2. Remote catch-up: pull remote changes, safely materializing new/updated files and quarantining remotely deleted files.
      3. Local scan: walk local vault and compute SHA-256 hashes.
      4. Safe reconciliation: run `buildSyncPlan`, check for conflicts or blockers.
      5. Execution: in `--apply` mode, execute push uploads (chunks first, then note docs) and logical deletions; record exact provenance in SQLite.
      6. Final convergence check: re-verify local hashes against remote revisions to confirm complete convergence.
    - CLI `arm` command:
      - Validates remote admission and configuration.
      - Issues 5-tuple bound grant via `WriteGrantRepo.issueGrant`.
      - Displays grant summary and arming token ID.
    - CLI `sync` command:
      - Emits backup warning banner (SAFE-07): "WARNING: Synchronization propagates creations, updates, and deletions across all clients. It is NOT an independent backup."
      - Checks active write grant for the current vault and database; if missing, expired, or drifted, aborts with `MUTATION_VIOLATION` (or runs read-only in `--dry-run`).
      - In `--dry-run` mode: runs read-only probe and local scan, serializes planned actions to stdout/JSON Lines, and ensures zero mutations.
      - In `--apply` mode: executes `SyncCoordinator` and reports structured outcome.
    - Update `src/cli/index.ts` to expose `arm` and `sync` commands.
  </behavior>
