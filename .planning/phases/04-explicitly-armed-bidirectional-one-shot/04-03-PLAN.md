<task type="auto" tdd="true">
  <name>Task 2: Bidirectional SyncPlan and Conflict Reconciler</name>
  <files>src/domain/sync-plan.ts, tests/unit/sync-plan.test.ts, tests/unit/conflict-reconciler.test.ts</files>
  <behavior>
    - `buildSyncPlan(remoteInventory, localScan, provenanceMap, options)` computes the bidirectional action set:
      - `pull-create` / `pull-update`: remote file is newer than provenance and local file is untouched.
      - `push-create`: local file is new (not in provenance, not on remote).
      - `push-update`: local file has changed (hash != provenance), remote is at proven base revision.
      - `push-delete`: local file was deleted, remote is at proven base revision -> logical deletion.
      - `rename-case` / `rename-cross`: detected renames preserving lineage.
      - `noop`: local, remote, and provenance hashes and revisions are identical.
      - `conflict`: both local and remote changed independently.
    - Conflict reconciliation:
      - If remote leaves have different revisions but identical content hashes, safely collapse them (SYNC-06).
      - If local content matches one remote leaf, choose that leaf.
      - If local and remote content differ with no clear ancestry, mark action as `conflict` and block mutation of that file to preserve both branches (SYNC-06, SYNC-07).
    - `serializeSyncPlan(actions)` produces structured representation for CLI and dry-run display (SYNC-08).
  </behavior>

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|

| T-04-08 | Information Disclosure | `VaultScanner` | medium | mitigate | Enforce ignore policy (`shouldBeIgnored`, `.obsidian`, hidden files) during local scanning so internal files are never pushed. |
