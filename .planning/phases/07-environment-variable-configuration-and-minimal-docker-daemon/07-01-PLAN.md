<threat_model>
<trust_boundaries>
- Environment Variables (`process.env`) -> Config Loader (Untrusted input boundary)
- Environment Secrets -> Loggers / Diagnostics (Information disclosure boundary)
</trust_boundaries>
<threats>
- T-07-01: Information Disclosure / Secret Leakage via Environment Variables — `LIVESYNC_COUCHDB_PASSWORD` or `LIVESYNC_ENCRYPTION_PASSPHRASE` leaked in plain text via unhandled exceptions or logger metadata if not registered with `SecretRedactor`. (Mitigation: Loader immediately registers any resolved plaintext password or passphrase with `SecretRedactor`).
- T-07-02: Path Traversal / Host Filesystem Tampering via Environment Variables — Malicious or accidental `LIVESYNC_VAULT_PATH=/` or `LIVESYNC_VAULT_PATH=~` mounts leading to deletion or mutation of host system files. (Mitigation: Retain and strictly enforce CONF-03 path safety checks on all environment-derived paths).
</threats>
</threat_model>

<task type="auto" tdd="true">
  <name>Task 1: Implement environment variable mapping, synthesis, and secret redaction in loader</name>
  <files>src/config/loader.ts, src/config/schema.ts, tests/unit/env-loader.test.ts</files>
  <behavior>
    - `loadConfig(configFilePath?: string, env: NodeJS.ProcessEnv = process.env, redactor?: SecretRedactor)`:
      - If `configFilePath` is provided: reads and parses YAML file, then overlays non-empty `LIVESYNC_*` environment variables on top of file configuration.
      - If `configFilePath` is omitted or undefined: synthesizes configuration object purely from `LIVESYNC_*` environment variables.
      - Supported mapping with aliases:
        - `LIVESYNC_COUCHDB_URL` / `COUCHDB_URL` -> `remote.url`
        - `LIVESYNC_COUCHDB_DATABASE` / `LIVESYNC_DATABASE_NAME` / `COUCHDB_DATABASE` -> `remote.database`
        - `LIVESYNC_COUCHDB_USER` / `LIVESYNC_COUCHDB_USERNAME` / `COUCHDB_USER` -> `remote.username`
        - `LIVESYNC_COUCHDB_PASSWORD` / `COUCHDB_PASSWORD` -> `remote.password`
        - `LIVESYNC_VAULT_PATH` / `VAULT_PATH` -> `vault.path`
        - `LIVESYNC_VAULT_DEDICATED` -> `vault.dedicated` (coerced boolean: "true"/"1" -> true)
        - `LIVESYNC_DATABASE_PATH` / `LIVESYNC_STATE_PATH` -> `state.path`
        - `LIVESYNC_ENCRYPTION_PASSPHRASE` / `LIVESYNC_PASSPHRASE` -> `encryption.passphrase`
        - `LIVESYNC_ENCRYPTION_ENABLED` -> `encryption.enabled` (coerced boolean; default true if passphrase provided)
        - `LIVESYNC_WRITE` / `LIVESYNC_WRITE_MODE` -> `cli.write`
        - `LIVESYNC_PERIODIC_SCAN_SEC` -> `cli.periodicScanSec` (parsed integer)
        - `LIVESYNC_CONCURRENCY` -> `cli.concurrency` (parsed integer)
        - `LIVESYNC_DEBOUNCE_MS` -> `cli.debounceMs` (parsed integer)
      - Validates against `LiveSyncConfigSchema.safeParse()`.
      - Resolves secrets and immediately registers discovered `remotePassword` and `encryptionPassphrase` with `redactor`.
      - Enforces CONF-03 path safety (reject root `/`, reject home `~`, reject overlapping vault/state directories).
  </behavior>
  <action>
Create `tests/unit/env-loader.test.ts` testing purely environment-driven configuration, environment overrides over YAML files, secret redaction registration, boolean/integer coercion, and path safety validation. Refactor `src/config/loader.ts` to implement environment synthesis.

  <verify>

  </verify>
  <done>
