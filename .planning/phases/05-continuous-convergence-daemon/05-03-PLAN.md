<threats>
- T-05-06: Concurrent Interleaving & Race Conditions — Simultaneous edits or notifications on the same file path trigger interleaving push and pull writes, causing lost edits or revision conflicts. (Mitigation: Per-path async mutex lock in FileWorkerPool; dirty flag re-queues file for single re-evaluation if modified while busy).
- T-05-07: Unbounded Memory Growth via Queue Flooding — Rapid mass file modifications exhaust process memory. (Mitigation: Queue cap at 10,000 items with coalescing into a single full-scan flag).
- T-05-08: Silent Write Operation on Revoked Grant / Config Drift — Remote settings hash drifts or grant expires during continuous run, permitting unauthorized remote writes. (Mitigation: DaemonStateMachine drops write capability immediately on drift detection, transitions to DEGRADED_READ_ONLY, and logs high-severity SAFE-06 alert).
</threats>
</threat_model>

  <name>Task 1: Implement FileWorkerPool with per-path async mutex and bounded concurrency</name>
  <files>src/daemon/file-worker-pool.ts, tests/unit/file-worker-pool.test.ts</files>
  <behavior>
    - Manages a FIFO queue of file invalidation hints with maximum capacity (default 10,000 items).
    - Enforces maximum active concurrency limit (default 4 active workers).
    - Per-path serialization: If a task for path `X` is currently running, any new hint for `X` marks path `X` as dirty instead of spawning a concurrent worker. When the active worker for `X` completes, it re-runs reconciliation once if marked dirty, then releases the path lock.
    - If the queue reaches capacity, coalesces pending tasks and emits a `QUEUE_OVERFLOW` event that triggers a full rescan.
    - Exposes `enqueue(hint)`, `drain(timeoutMs)`, `pause()`, `resume()`, `clear()`, `getActiveCount()`, `getPendingCount()`.
  </behavior>

<task type="auto" tdd="true">
  <name>Task 2: Implement FileReconciler and DaemonStateMachine</name>
  <files>src/daemon/file-reconciler.ts, src/daemon/daemon-state.ts, tests/unit/file-reconciler.test.ts, tests/unit/daemon-state.test.ts</files>
  <behavior>
    - `FileReconciler`:
      - Given a path hint, performs an authoritative ground-truth re-read: checks local disk stat/hash, checks remote doc metadata/leaves via guarded fetch, checks SQLite provenance.
      - Uses `LoopSuppressor` to filter out identical echoes.
      - If local changed: pushes chunks first, updates remote metadata doc with new rev, records provenance in SQLite.
      - If remote changed: fetches chunks, reconstructs content, writes to temp staging file, verifies SHA-256, atomically renames to target path, records provenance in SQLite.
      - If conflict detected: handles conflict preservation (creates conflict copy or retains both branches safely).
      - If file deleted locally: performs LiveSync logical deletion if armed for write.
      - If file deleted remotely: unlinks local file with quarantine preservation if modified.
    - `DaemonStateMachine`:
      - States: `INITIALIZING`, `CATCHING_UP`, `HEALTHY_BIDIRECTIONAL`, `DEGRADED_READ_ONLY`, `BLOCKED`, `STOPPING`, `STOPPED`.
      - Validates write grant and remote fingerprint binding before permitting `HEALTHY_BIDIRECTIONAL`.
      - If grant verification fails or drifts at runtime, transitions immediately to `DEGRADED_READ_ONLY`, revokes `WriteCapability`, and logs diagnostic.
      - If fatal storage corruption or protocol error occurs, transitions to `BLOCKED`.
  </behavior>

<task type="auto" tdd="true">
  <name>Task 3: Implement ContinuousEngine with finite catch-up and periodic scan coordination</name>
  <files>src/daemon/continuous-engine.ts, tests/unit/continuous-engine.test.ts</files>
  <behavior>
    - `ContinuousEngine` coordinates full daemon operation:
      1. Preflight: Performs remote admission negotiation (DAEM-01) and write grant verification if in write mode.
      2. Catch-up: Executes complete one-shot `SyncCoordinator.sync()` pass (DAEM-02) before enabling live intake.
      3. Live intake: Attaches `FsWatcher` and `ChangesConsumer` to feed hints into `FileWorkerPool`.
      4. Periodic scan: Schedules periodic full reconciliation pass (default every 300s) (DAEM-06) to heal any dropped OS events.
      5. Error recovery: Schedules post-error rescan upon network reconnection or worker pool error.
      6. Checkpoint persistence: Commits contiguous sequence checkpoints to SQLite via `CheckpointWindow`.
  </behavior>
