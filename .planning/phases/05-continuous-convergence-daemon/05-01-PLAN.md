<objective>
Implement the local filesystem watcher, event debouncer, and self-reflection loop suppressor for the continuous convergence daemon.

Purpose: The daemon must monitor the local vault for changes without entering infinite ping-pong loops when applying remote updates, and without overwhelming the system during rapid editor save bursts (atomic swap/rename patterns).
Output: `src/daemon/fs-watcher.ts`, `src/daemon/loop-suppressor.ts`, and comprehensive unit test suites.
</objective>

<threat_model>
<trust_boundaries>
- Local filesystem events (Chokidar) -> Daemon Invalidation Pipeline (Untrusted external OS signals)
- Provenance SQLite Database -> Loop Suppressor (Trusted ground truth)
</trust_boundaries>
<threats>
- T-05-01: Denial of Service via Watcher Flooding — Rapid burst saves (e.g. editor temp-file replacement) flood the event queue and exhaust CPU/memory. (Mitigation: 300ms trailing debouncer per path + ignore rules for swap/tmp files).
- T-05-02: Self-Reflection Ping-Pong Loop — Local disk writes triggered by remote pulls cause watcher events that re-push to CouchDB, creating infinite revision loops. (Mitigation: Provenance content SHA-256 and remote _rev comparison before admitting file to work queue).
- T-05-03: Path Traversal / Symlink Escape — Watcher receives events outside vault root or traverses forbidden symlinks. (Mitigation: Normalize paths using PathPolicy; reject any paths outside vault or within ignored internal trees).
</threats>
</threat_model>

<task type="auto" tdd="true">
  <name>Task 2: Implement LoopSuppressor with SHA-256 and remote rev echo filtering</name>
  <files>src/daemon/loop-suppressor.ts, tests/unit/loop-suppressor.test.ts</files>
  <behavior>
    - `LoopSuppressor` provides methods: `shouldSuppressLocalEvent(vaultRoot, relativePath, provenanceRepo)` and `shouldSuppressRemoteEvent(relativePath, remoteRev, provenanceRepo)`.
    - For local events: Reads the file from disk (or handles non-existence for unlinks), computes SHA-256 hash. Reads provenance from `provenanceRepo.getProvenance(relativePath)`.
      - If local file exists and `sha256 === provenance.contentSha256`: returns `true` (suppress: content unchanged from last sync).
      - If local file was deleted and provenance indicates it is already marked deleted or missing: returns `true` (suppress).
      - Otherwise returns `false` (admit: genuine local modification).
    - For remote events: Reads provenance for `relativePath`.
      - If `provenance.remoteRevision === remoteRev`: returns `true` (suppress: this client generated this revision).
      - Otherwise returns `false` (admit: genuine remote modification).
    - Handles mtime updates: minor mtime changes with identical SHA-256 are suppressed cleanly without warning.
  </behavior>
  <action>
Implement `src/daemon/loop-suppressor.ts`. Write comprehensive unit tests in `tests/unit/loop-suppressor.test.ts` testing local SHA-256 matches, local modifications, remote rev matches, new remote revisions, and deleted file cases against an in-memory or SQLite provenance repository.
  </action>

  </verify>
