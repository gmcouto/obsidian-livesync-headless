<threat_model>
<trust_boundaries>
- Remote CouchDB HTTP Stream -> ChangesConsumer (Untrusted external stream)
- ChangesConsumer -> CheckpointWindow & SQLite Checkpoint Repository (Trusted persistent state)
</trust_boundaries>
<threats>
- T-05-03: Malformed Stream / Parser Injection — Network payload corruption or injection in NDJSON stream crashes daemon process. (Mitigation: Robust line accumulator buffer, strict JSON parsing within try/catch, heartbeat empty-line filtering).
- T-05-04: Network Flapping / DoS on Reconnection — Reconnect loop overwhelms CouchDB server during outage recovery. (Mitigation: Jittered exponential backoff with 500ms min, 30s max, and ±25% random jitter).
- T-05-05: Premature Checkpoint Advancement — Advancing CouchDB sequence token before in-flight file processing completes permanently drops changes on crash. (Mitigation: Monotonic contiguous CheckpointWindow; checkpoint commits only the highest sequence where all predecessors are verified).
</threats>
</threat_model>

<task type="auto" tdd="true">
  <name>Task 2: Implement ReconnectionManager with jittered exponential backoff</name>
  <files>src/daemon/reconnection-manager.ts, tests/unit/reconnection-manager.test.ts</files>
  <behavior>
    - `ReconnectionManager` manages backoff state: `attempt`, `baseDelayMs` (default 500ms), `maxDelayMs` (default 30,000ms), `jitterFactor` (default 0.25).
    - `getNextDelay()` calculates `delay = min(maxDelay, baseDelay * 2^attempt) ± (jitterFactor * exponential)`.
    - Ensures delay is never below `baseDelayMs` and capped at `maxDelayMs`.
    - `recordSuccess()` resets the attempt counter to 0.
    - `scheduleRetry(callback, signal)` executes callback after delay, cancellable via AbortSignal.
  </behavior>

<task type="auto" tdd="true">
  <name>Task 3: Implement Monotonic Checkpoint Window Manager with error fencing</name>
  <files>src/daemon/checkpoint-window.ts, tests/unit/checkpoint-window.test.ts</files>
  <behavior>
    - `CheckpointWindow` maintains an ordered queue of in-flight sequence tokens received from the changes feed.
    - `trackSequence(seq)` registers a received sequence token in pending state.
    - `markCompleted(seq)` marks a sequence as successfully reconciled and verified.
    - `markFailed(seq, error)` marks a sequence as failed/blocked.
    - `getContiguousCommitSequence()` returns the highest sequence token where ALL preceding sequences have completed successfully. If any earlier sequence is pending or failed, returns only up to the last consecutive completed token.
    - `commit(checkpointRepo, peerId)` persists the highest contiguous sequence to SQLite `pull_checkpoints` and purges older tracked entries.
  </behavior>
